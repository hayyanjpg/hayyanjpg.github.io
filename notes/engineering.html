ENGINEERING NOTES

Hal-hal yang saya pelajari dari proyek, ditulis pendek supaya mudah dibaca orang yang nggak punya waktu buka case study panjang.

01 / DATASET BERSIH ITU BUKAN PELENGKAP

DARI RECONCILIATION PIPELINE

Di pipeline rekonsiliasi, aturan SQL yang sama dijalankan dua kali: sekali pada dataset kotor, sekali pada dataset bersih. Di dataset kotor cuma 2 dari 16 check yang lolos. Di dataset bersih, 16 dari 16 lolos.

Kalau saya hanya punya dataset kotor, saya bisa mengklaim "semua anomali terdeteksi" — tapi itu bisa berarti sistem menuduh semuanya. Dataset bersih adalah cara membuktikan aturannya nggak bikin false positive. Dua angka itu baru bermakna kalau dibaca berdua.

02 / FAKE OBJECT BISA MENYEMBUNYIKAN BUG PRODUKSI

DARI BOGANA AI ERP

Restock bahan diproduction selalu balas 500. Akarnya: StockRepository.restock() memanggil _require_pool() yang ternyata cuma ada di repository lain. Test API lolos karena memakai FakeStockRepository — jalur repository asli nggak pernah jalan.

Sejak itu saya sengaja menyisipkan satu jalur real repository di regression test, dengan pool dan transaksi yang masih di-fake. Fake tetap dipakai untuk kecepatan, tapi bukan untuk menutup kelas yang paling rawan.

03 / VALIDASI SQL NGGAK BISA CUMA CARI KATA TERLARANG

DARI SIFT TEXT-TO-SQL

Kalau validator cuma mencari string seperti DROP, kata itu bisa disisipkan di komentar atau di dalam literal. Di SIFT saya pakai validator berbasis state machine yang paham komentar, string, quoted identifier, dan dollar-quoted block. Hasil LLM juga dibersihkan dulu dari markdown fence dan prefiks sql:.

SELECT jalan di transaksi read-only dengan timeout 60 detik. DML ditahan dan baru jalan setelah konfirmasi, dengan validasi ulang. Yang belum ada: audit log dan role database terpisah — itu masih saya sebut terus terang di README.
